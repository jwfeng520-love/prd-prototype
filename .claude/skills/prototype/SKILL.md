# /prototype — 生成交互原型

## 描述
从功能描述生成单或多页面文件交互式 HTML 可商用的高保真原型（CSS/JS 内联），双击即可在浏览器中打开，无需构建工具。

## 输入
用户应提供（缺失项生成前提问）：
1. 功能/产品描述
2. 核心页面/视图
3. 关键交互（Tab切换、导航、表单、模态框等）

## 生成前确认
启动时主动向用户确认以下选项（以对话形式，非表单）：

### 视觉风格
- **iOS 风格**：底部 Tab Bar + 顶部 Navigation Bar，遵循 Apple UI Designer 设计语言
- **Web 风格**：侧边栏或顶部导航
- **Material Design**：浮动按钮 + 卡片 + 波纹反馈

### 设备适配
⚠️ **如用户未指明设备端，必须主动询问用户选择：**
- **手机端**：375px 容器（iOS/移动端风格）
- **桌面端**：自适应容器（全屏宽，响应式）
- **双端适配**：两套视图

---

## Apple UI Designer 指南（iOS 风格专用）

当用户选择 **iOS 风格** 时，必须遵循以下 Apple 设计语言规范。

### 设计哲学
- **Native over custom** — 原生感优先，自定义克制
- **Subtle over expressive** — 克制胜过张扬
- **Calm, confident, and human** — 冷静、自信、人性化
- "Feels obvious" rather than "looks fancy" — 好用 > 好看
- 避免花哨的 UI 噱头，一切对 iOS 用户来说应感到自然和熟悉

### 视觉规范
- **字体**：系统优先（SF Pro / -apple-system），用字号和字重建立层次，而非颜色
- **色彩**：中性色调为主（白色/灰白背景、系统灰度），强调色克制使用
- **质感**：适当使用毛玻璃（translucency/blur）和层级深度
- **边框**：禁止硬边框，用间距和分组来区分内容
- **圆角**：系统级圆角（10-14px），保持一致性

### 布局与结构
- 遵循 iOS 原生布局模式
- Safe-area 意识（状态栏/底部 Home Indicator 留白）
- 舒适的触控目标（≥ 44pt）
- 垂直滚动作为主要导航方式
- 卡片轻量、系统化，避免信息密度过高
- 清晰优先，信息密度克制

### 组件规范
| 组件 | 规范 |
|------|------|
| **按钮** | 系统按钮行为，主次层次清晰，圆角 10-12px |
| **列表** | iOS 风格列表节奏，分隔线或间距二选一，不能同时用 |
| **导航栏** | 标准导航栏 + 大标题（适当场景） |
| **模态/Sheet** | 优先底部 Sheet，支持拖拽关闭手势 |
| **Tab 栏** | 系统 Tab Bar，图标+标签，active 态 tint color 高亮 |

### 交互与动效
- 平滑自然缓动（无弹性动画，除非是系统级交互）
- 动效用于解释层级关系，而非装饰
- 使用 fade、slide、subtle scale 三种基础动效
- 所有过渡感觉冷静而有意图

### 绝对避免清单
- ❌ 过度设计的自定义组件
- ❌ 花哨的 UI 噱头或特效
- ❌ 重渐变或霓虹色
- ❌ 硬边框或轮廓线
- ❌ 密集杂乱的布局
- ❌ 非标准导航模式
- ❌ 不要把产品实现逻辑描述呈现在原型

### 决策规则
- 不要过度设计。感觉不必要就移除
- 清晰和熟悉感是最高优先级
- 有疑问时遵循 iOS 系统默认
- 宁缺毋滥，优先减法

### 最终标准
**每个界面应让人觉得它就是 Apple 原生应用的一部分 — 冷静、自信、原生、理所当然。**

## 步骤

### Step 1: 理解范围
确认视觉风格 + 设备适配 + 功能范围。

### Step 2: 应用设计系统
根据确认的视觉风格，应用对应的设计 Token 和组件模式：

**设计 Token 基准**（所有风格通用）：
- 品牌色（primary/success/warning/danger）
- 中性色（bg/surface/border/text）
- 间距（4px 基准）、圆角、阴影
- 字体栈（系统字体优先）

**组件库**（通过 CSS 类名实现，无外部依赖）：
- 导航栏（NavBar）、Tab 栏、卡片、按钮（主/次/危险）
- 表单输入框、模态框、Toast 通知
- 骨架屏加载、空状态占位

**iOS 风格额外要求：**
- 应用 Apple UI Designer 设计哲学（native, subtle, calm）
- 使用 iOS 设计 Token 覆盖（--accent: #007AFF 等）
- 毛玻璃效果（backdrop-filter: blur()）
- 大标题导航栏 + 细分隔线
- 底部 Sheet 而非居中模态框
- 触感反馈（:active 缩放）
- 禁止硬边框，用间距分组

### Step 3: 构建原型
1. **容器**：手机端用 `.phone > .app`（375px 圆角容器），桌面端用 `.desktop`（全屏宽自适应布局），双端适配则提供两套
2. **布局**：手机端 → 竖屏上下结构（导航栏 + 内容 + Tab 栏/底部栏）；桌面端 → 侧边栏 + 主内容区 + 可选右侧面板
3. **导航**：多 Tab 时创建底部 Tab 栏（手机）或侧边导航（桌面）
4. **视图**：每个 Tab 对应的独立内容区
5. **子页面**：下钻/二级页面用覆盖层（手机用 slideInRight 动画，桌面用面板展开）
6. **数据**：使用具体的模拟数据（非 Lorem ipsum），至少 4-6 条
7. **交互**：Tab 切换、子页面导航、模态框、表单、加载模拟、Toast 反馈
8. **样式**：应用设计 Token、hover/active 触感反馈、过渡动画

**iOS 风格构建额外要求：**
- 应用 Apple UI Designer 视觉规范（中性色调、系统字体、毛玻璃）
- 布局遵循 iOS 原生模式，safe-area 感知
- 组件按 Apple 组件规范实现
- 动效使用 fade/slide/subtle scale，冷静自然
- 逐条对照"绝对避免清单"检查设计

### Step 4: 交互覆盖检查
- [ ] Tab 切换可工作
- [ ] 加载中状态（setTimeout 模拟）
- [ ] 空状态（首次加载时）
- [ ] Toast 操作反馈
- [ ] 触感反馈（:active 缩放）
- [ ] 至少一个模态框/底部 Sheet 交互
- [ ] 页面间平滑过渡

**iOS 风格额外检查：**
- [ ] 无硬边框，用间距分组
- [ ] 无重渐变或霓虹色
- [ ] 色彩中性克制，强调色少量使用
- [ ] 导航模式为标准 iOS 模式
- [ ] 字号/字重建立层次，而非颜色
- [ ] 触控目标 ≥ 44pt
- [ ] 动效冷静自然，非弹性/装饰性动画

### Step 5: 保存
保存到 `projects/<项目名>/prototypes/<功能名>.html`

### Step 6: 质量检查
- [ ] 单文件，无外部依赖
- [ ] 所有交互元素可工作
- [ ] 无死链接/无功能按钮
- [ ] 具体内容，非占位符
- [ ] 在容器内响应式良好
- [ ] 符合所选视觉风格规范

### Step 7: 总结
告知用户：
- 保存路径（可直接在浏览器打开）
- 实现了哪些页面和交互
- 建议下一步迭代方向

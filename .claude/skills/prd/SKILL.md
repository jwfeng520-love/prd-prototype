# /prd — 生成结构化 PRD

## 描述
从产品概念或功能描述出发，生成结构化、完整的 PRD（产品需求文档）。

## 输入
用户应提供（缺失项主动提问）：
1. 产品/功能名称和一句话描述
2. 目标用户（如不知，生成后让用户确认）
3. 核心功能（列表或自由描述）
4. 已知约束（技术、时间、业务）
5. 关联原型路径（如有）

## 步骤

### Step 1: 澄清范围
检查输入是否完整，如缺失关键信息，提问补充。确认范围后再生成。

默认语言：中文。如果用户指明其他语言，使用指定语言。

### Step 2: 加载模板
读取 `templates/prd-template.md` 作为结构框架。

### Step 3: 生成 PRD
逐节填充模板内容：

| 章节 | 要点 |
|------|------|
| 执行摘要 | 最后写，提炼全文 |
| 问题陈述 | 如果用户描述模糊，提供 2-3 种可能的表述 |
| 用户画像 | 如未提供，生成 2-3 个典型画像 |
| 用户故事 | 5-10 条，按 P0/P1/P2 排序 |
| 功能需求 | 每个功能描述完整流程 + 引用数据表 + 状态覆盖 |
| 验收标准 | 每个故事至少 4 个 Given-When-Then 场景 |
| 数据库设计 | 每张表列出完整字段，字段必须包含中文说明列 |
| 非功能需求 | 默认包含性能、无障碍、安全、兼容性 |
| 技术方案 | 包含技术栈表、系统架构图、项目目录结构、关键技术决策 |
| UI/UX 风格 | 根据项目类型从风格指南表自动匹配推荐风格 |
| 不在此范围 | 明确排除项，和包含项同样重要 |
| 风险 | 3-5 条，带概率和影响评级 |
| 开放问题 | 3-5 个需干系人输入的问题 |

### Step 4: 保存
保存到 `projects/<项目名>/prd/<功能名>-prd.md`
如项目目录不存在，先创建标准项目结构。

### Step 5: 输出摘要
生成完毕后，提供：
- 一段 PRD 执行摘要
- 保存文件路径
- 2-3 个待决策的开放问题
- 下一步建议（原型 / 技术评审 / 故事拆分）
